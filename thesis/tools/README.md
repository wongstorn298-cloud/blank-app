# เครื่องมือสร้างเล่มโครงงาน

สร้างเล่มรูปแบบ มทส. จากร่าง Markdown ใน `thesis/drafts/`

```bash
python3 thesis/tools/build_thesis.py
```

ผลลัพธ์อยู่ใน `thesis/build/`

ถ้าต้องการลองสร้างจากร่างชุดอื่นโดยไม่ทับเล่มจริง ใช้ `--drafts` และ `--out` (ค่าเริ่มต้นคือ `thesis/drafts` และ `thesis/build`)

```bash
python3 thesis/tools/build_thesis.py --drafts /path/ร่างทดลอง --out /path/ผลทดลอง
```

- `เล่มโครงงาน.docx` คือไฟล์ Word ที่ใช้แก้ต่อและส่ง
- `เล่มโครงงาน.pdf` คือไฟล์สำหรับดูตัวอย่าง แปลงด้วย LibreOffice
- `build-log.txt` คือผลตรวจอัตโนมัติ มีเลขอ้างอิงเดิมเทียบกับเลขใหม่ และรายการ `[รอใส่]` ทั้งหมด
- `figures/` เก็บภาพ Mermaid ที่แปลงแล้ว ชื่อไฟล์มาจาก hash ของโค้ด ถ้าโค้ดแผนภาพไม่เปลี่ยน สคริปต์จะใช้ภาพเดิมโดยไม่ต้องแปลงใหม่

## สิ่งที่ต้องมีในเครื่อง

- Python 3 และ `python-docx` ส่วน Pillow จำเป็นเมื่อต้องใส่ภาพ
- LibreOffice (`soffice`) ใช้คำนวณเลขหน้าในสารบัญและแปลงเป็น PDF ถ้าไม่มี จะได้แค่ .docx และต้องกด F9 ใน Word เพื่อสร้างสารบัญเอง
- Node.js กับ Playwright Chromium และแพ็กเกจ `mermaid` ใช้แปลงแผนภาพ Mermaid ติดตั้งครั้งแรกด้วย `cd thesis/tools && npm install` ถ้าไม่มีเครื่องมือชุดนี้ สคริปต์จะใส่กรอบแทนภาพ
- ฟอนต์ TH SarabunPSK ถ้าเครื่องไม่มี แต่มี Laksaman (แพ็กเกจ `fonts-tlwg-laksaman-otf` ซึ่งออกแบบให้ขนาดเท่า TH SarabunPSK) สคริปต์จะใช้ Laksaman สร้าง PDF แทนเป็นการชั่วคราว ไฟล์ .docx ยังกำหนดฟอนต์เป็น TH SarabunPSK เหมือนเดิม

## วิธีที่สคริปต์อ่านร่าง

- ไฟล์ `NN-*.md` ต้องขึ้นต้นด้วย `# บทที่ N ชื่อบท` หัวข้อย่อยใช้ `##` สำหรับ x.y และ `###` สำหรับ x.y.z
- ข้อความ `> ...` (blockquote) ถือเป็นหมายเหตุถึงบรรณาธิการ สคริปต์จะไม่นำไปใส่ในเล่ม
- ส่วน `## เอกสารอ้างอิง...` หรือ `## แหล่งอ้างอิง...` ท้ายบท สคริปต์จะรวมทุกบทเป็นส่วนเอกสารอ้างอิงเดียว ตัดรายการซ้ำออกโดยเทียบ URL หรือชื่อเรื่อง และเรียงเลขใหม่ตามลำดับที่อ้างครั้งแรกทั้งเล่ม การเปลี่ยน `[n]` และ `[อ้างอิง: ...]` ในเนื้อหาทำเฉพาะในเล่มที่สร้าง ไฟล์ร่างไม่ถูกแก้
- ชื่อตารางต้องเป็นบรรทัด `ตารางที่ x.y ชื่อ` ที่อยู่เหนือตาราง Markdown
- `[รูปที่ x.y: คำอธิบาย]` จะกลายเป็นกรอบรอใส่ภาพพร้อมชื่อรูปใต้กรอบ ถ้ามีบล็อก ```` ```mermaid ```` อยู่ก่อนหน้า จะใส่ภาพที่แปลงจาก Mermaid แทนกรอบ
- ใส่ภาพจากไฟล์ด้วยบรรทัดเดี่ยว `![รูปที่ x.y: คำอธิบาย](../figures/ชื่อไฟล์.png)` path นับจากโฟลเดอร์ของไฟล์ร่าง (ร่างอยู่ที่ `thesis/drafts/` ภาพอยู่ที่ `thesis/figures/`) ใช้ได้ทั้ง PNG และ JPG
  - ภาพอยู่กึ่งกลาง ย่อให้กว้างไม่เกินความกว้างข้อความ (21 − 3.81 − 2.54 = 14.65 ซม.) และสูงไม่เกิน 60% ของความสูงข้อความ (ประมาณ 14.8 ซม.) โดยคงสัดส่วนเดิม ภาพเล็กจะไม่ถูกขยายเกินขนาดจริง ภาพแนวตั้ง เช่น ภาพหน้าจอโทรศัพท์ จะถูกจำกัดความสูงและอยู่กึ่งกลาง
  - ชื่อรูปอยู่ใต้ภาพ ("รูปที่ x.y" ตัวหนา) และเข้าสารบัญรูปเหมือนรูปแบบกรอบและ Mermaid ข้อความหลัง ` — ` ในคำอธิบายจะไม่นำไปใส่ในชื่อรูป
  - ถ้าไม่พบไฟล์ภาพหรือเปิดไม่ได้ จะใส่กรอบรอใส่ภาพแทน และบันทึกบรรทัด `[ภาพ] ERROR ...` ใน `build-log.txt`
  - การตรวจเลขรูป (เรียงต่อเนื่อง ถูกอ้างถึงในเนื้อหา และอ้างถึงก่อนรูปปรากฏ) ใช้กับรูปทุกแบบเหมือนกัน
  - ภาพหน้าจอต้องใช้ข้อมูลจำลองเท่านั้น
- สมการเขียนแบบ `$$ ... \tag{x.y} $$` ได้ แต่ระบบแปลง LaTeX ได้แค่แบบง่าย คือตัวห้อย ตัวยก `\text` และ `\frac`
- ข้อความ `[รอใส่...]` จะถูกไฮไลต์สีเหลือง
- ถ้ามีไฟล์ `*บทคัดย่อ*.md`, `*Abstract*.md`, `*กิตติกรรมประกาศ*.md` หรือ `*ภาคผนวก*.md` สคริปต์จะใช้เนื้อหาจากไฟล์นั้น ถ้าไม่มี จะใส่ข้อความ `[รอใส่]` ไว้แทน

ข้อมูลบนปก เช่น อาจารย์ที่ปรึกษา รายวิชา และภาคการศึกษา แก้ได้ที่ตัวแปร `META` ตอนต้นของ `build_thesis.py`

## ไฟล์ในโฟลเดอร์นี้

| ไฟล์ | หน้าที่ |
|---|---|
| `build_thesis.py` | สคริปต์หลัก แปลง Markdown เป็น Word ตรวจร่าง และเขียน log |
| `lo_update.py` | ใช้ LibreOffice ผ่าน UNO ปรับปรุงสารบัญ แล้วส่งเลขหน้ากลับมาให้สคริปต์หลัก |
| `render_mermaid.js` | ใช้ Chromium ของ Playwright แปลง Mermaid เป็น PNG โดยไม่ต้องใช้อินเทอร์เน็ต |
| `package.json` | ระบุเวอร์ชันของแพ็กเกจ `mermaid` |
