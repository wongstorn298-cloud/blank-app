# คำถามถึงเจ้าของโครงงาน (ข้อมูลที่ต้องเติมใน `[รอใส่: ...]`)

รวบรวมจากร่างบทที่ 1–3 ตอบสั้น ๆ ได้เลย ข้อที่ตอบไม่ได้หรือเปิดเผยไม่ได้ให้บอกว่า “ตัดออก”
ข้อที่ตอบแล้วย้ายไปไว้ท้ายไฟล์ พร้อมคำตอบ (นำไปใส่ในเล่มแล้ว)

## ยังไม่ได้ตอบ

### ข้อมูลทั่วไป (จาก CLAUDE.md)

1. ชื่ออาจารย์ที่ปรึกษา รหัสวิชา ภาคการศึกษา และวันส่งเล่ม

### บทที่ 1 บทนำ

2. พื้นที่รับผิดชอบของศูนย์พิสูจน์หลักฐาน 3 (จังหวัดที่ส่งคดีมาตรวจ) หรือคำบรรยายสั้น ๆ ที่เปิดเผยได้ (หัวข้อ 1.1)
3. จำนวนคดีส่งตรวจต่อปีโดยประมาณ ถ้าเปิดเผยได้ ถ้าไม่ได้จะตัดออก (หัวข้อ 1.1)
4. จะให้เจ้าหน้าที่จริงทดลองใช้หรือทำแบบประเมินความพึงพอใจหรือไม่ (หัวข้อ 1.5.1 ขั้นตอนที่ 9)
5. ชื่อเดือนของภาคการศึกษาที่ทำโครงงาน (4 เดือน / 16 สัปดาห์) และช่วงที่ทำแต่ละขั้นตอนจริง (ตารางที่ 1.1)

### บทที่ 2 ทฤษฎีและงานวิจัยที่เกี่ยวข้อง

8. คำอธิบายหน่วยงานโดยย่อ (สังกัด ที่ตั้ง พื้นที่รับผิดชอบ) และแหล่งอ้างอิงที่เปิดเผยได้ เช่น เว็บไซต์ของหน่วยงาน (หัวข้อ 2.1.1)
9. ลำดับขั้นตอนรับคดี → มอบหมายผู้ตรวจ → ตรวจเสร็จ → รับผล ในหัวข้อ 2.1.2 ตรงกับการทำงานจริงหรือไม่ มีขั้นตอนใดขาด (หัวข้อ 2.1.2)
11. แหล่งอ้างอิงโควตาข้อความฟรีต่อเดือนของ LINE Official Account ในประเทศไทย: ทีมจะค้นจากหน้าแพ็กเกจของ LINE for Business ประเทศไทยต่อ ถ้าเจ้าของมีหน้าจอแพ็กเกจในบัญชีของตนก็ส่งมาได้ (หัวข้อ 2.4.2 และ 3.5.3)
12. หน่วยงานมีเจ้าหน้าที่คุ้มครองข้อมูลส่วนบุคคล (DPO) หรือแนวปฏิบัติ PDPA ภายในที่อ้างอิงได้หรือไม่ ถ้าไม่มี ทีมจะตัดย่อหน้าเรื่องข้อยกเว้นตามมาตรา 4 ออก (หัวข้อ 2.6.1)

### บทที่ 3 การออกแบบระบบ

13. URL ต้นฉบับ พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 ในราชกิจจานุเบกษา (เว็บไซต์ปฏิเสธการเข้าถึงจากเครื่องที่ทีมใช้ร่าง) และมาตราที่เกี่ยวข้องกับหลักการแต่ละข้อในหัวข้อ 3.7

## งานที่ทีมจะเติมเอง (ไม่ต้องตอบ)

- แหล่งอ้างอิงเรื่ององค์ประกอบการทำความเข้าใจภาษาธรรมชาติ (intent/entity) ของแชตบอต (หัวข้อ 2.5.1): thesis-writer ค้นเพิ่ม
- รายการมาตรการทดแทนการตรวจ `x-line-signature` ที่ใช้จริง (หัวข้อ 3.5.3): รอโค้ดจาก linebot-dev
- รายละเอียดการตัดเลขคดีและข้อความที่ระบุตัวบุคคลก่อนส่งให้ Gemini ที่ทำจริง (หัวข้อ 3.5.2): รอโค้ดจาก linebot-dev

## ตอบแล้ว

6. **นิยาม “คดีค้าง”** — ตอบแล้ว: รายงาน**แยกกัน** เป็น “กำลังดำเนินการ” และ “เสร็จแล้ว รอรับผล” แสดงจำนวนแต่ละกลุ่มแยกกัน (แก้ในหัวข้อ 1.6, 3.2.3, 3.5.1)
7. **Turnaround time** — ตอบแล้ว: นับจากวันที่รับถึงวันที่ตรวจเสร็จ (แก้ในหัวข้อ 1.6)
10. **จำนวนสมาชิกกลุ่ม LINE** — ตอบแล้ว: ประมาณ 20 คน → push สรุปรายเดือน ≈ 20 ข้อความ/เดือน, มกราคม ≈ 40 ข้อความ (reply ไม่นับ) (แก้ในหัวข้อ 2.4.2, 3.5.3)
- **ข้อความที่ไม่ใช่คำสั่ง** — ตอบแล้ว: บอตเงียบ ไม่ตอบ (แก้ในหัวข้อ 2.5.1, 3.5.1, รูปที่ 3.9)
- **การส่งข้อความให้ Gemini** — ตอบแล้ว: ตัดเลขคดีและข้อความที่ระบุตัวบุคคลออกก่อนส่ง (แก้ในหัวข้อ 1.1, 1.3.1, 2.5, 3.1, 3.5.2)
- **คอลัมน์ User ID (LINE)** — ตอบแล้ว: ลบออกจาก Sheet จริง (แก้ในหัวข้อ 2.6.1, 3.2.1, 3.2.4, 3.7)
- **การตรวจ `x-line-signature`** — ตอบแล้ว: Apps Script `doPost` อ่านส่วนหัวไม่ได้ เขียนเป็นข้อจำกัดที่ทราบพร้อมมาตรการทดแทน (หัวข้อ 2.4.4, 3.5.3) เหลือรายการมาตรการที่ใช้จริงจาก linebot-dev
- **การควบคุมสิทธิ์ Dashboard** — ตอบแล้ว: Deploy แบบ User accessing the web app + ตรวจแท็บ “ผู้ใช้” ทุกครั้งที่ดึงข้อมูล + แชร์ Sheet แบบ Viewer เฉพาะคนในรายชื่อ (เขียนในหัวข้อ 3.4)
