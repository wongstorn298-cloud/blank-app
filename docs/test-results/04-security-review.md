## 4. ปัญหาที่พบ

### SR-1 (กลาง) การแบ่งชิ้นการตั้งค่าผ่ากลางอีโมจิ → อาจปฏิเสธทุกคนรวมเจ้าของ และบอตหยุด

- ที่มา: `saveConfig_` ตัด JSON ทุก 2,900 หน่วย UTF-16 ด้วย `json.slice(i, i + CFG.CHUNK_CHARS)` อีโมจิ 1 ตัวใช้ 2 หน่วย (surrogate pair) ถ้าขอบชิ้นตกกลางคู่ ชิ้นหนึ่งจะลงท้ายด้วยครึ่งแรก อีกชิ้นขึ้นต้นด้วยครึ่งหลัง
- ผลกระทบ: ถ้าที่เก็บ Script Properties แปลงข้อความเป็น UTF-8 แล้วแทนครึ่งอีโมจิด้วย U+FFFD (พฤติกรรมทั่วไปของการเข้ารหัส UTF-8 กับอักขระครึ่งคู่ **ยังไม่ได้ยืนยันกับ Apps Script จริง**) ลายเซ็นจะไม่ตรง `loadConfig_` โยน Error ทุกครั้ง → `checkAccess_` ปฏิเสธทุกคนรวมเจ้าของ (`config-broken`), บอตตอบ "อ่านข้อมูลคดีไม่ได้", สรุปรายเดือนไม่ส่ง · กู้ได้ทางเดียวคือแก้ `DASH_CFG_*` ใน editor ซึ่งพาไปสู่ SR-2
- ขั้นตอนโจมตี/เกิดโดยบังเอิญ: (ค) ผู้ดูแลเพิ่มผู้ใช้ที่ชื่อหรือหมายเหตุมีอีโมจิ (เกิดได้แม้ไม่ตั้งใจ เช่น "เจ้าหน้าที่ ก 😊") ผู้ดูแลที่ตั้งใจทำลายเลือกความยาวหมายเหตุคนก่อนหน้าให้ขอบชิ้นตกกลางอีโมจิได้ (ในชุดทดสอบลองไม่กี่ค่าก็เจอ)
- หลักฐาน: `security_review.js` กรณี SR-1 (ตารางข้อ 3 แถว 7)
- แนวทางแก้: ใน `saveConfig_` ถ้า `json.charCodeAt(end - 1)` เป็น high surrogate (0xD800–0xDBFF) ให้ตัดชิ้นสั้นลง 1 หน่วย · ใน `cleanText_` ตัดความยาวตามจุดรหัส (`Array.from(s).slice(0, max).join('')`) เพื่อไม่ให้เหลือครึ่งอีโมจิ · หรือตัดอีโมจิ/อักขระนอก BMP ออกจากชื่อและหมายเหตุ · ย้ายกรณี SR-1 เข้า run.js หลังแก้

### SR-2 (ต่ำ) ลบ `DASH_CFG_*` ขณะยังมี `CASES_SHEET_ID` → กลับไปใช้แท็บ ผู้ใช้ เดิม

### SR-4 (ต่ำ) `dailySummaryJob` เรียกได้จากลิงก์บอตแบบไม่ล็อกอิน (กันด้วย triggerUid อย่างเดียว)

### SR-5 (ต่ำ, ตามการออกแบบ) ผู้ดูแลทุกคนมีสิทธิ์เท่ากัน

- ผู้ดูแลที่ไม่หวังดี (ค) ทำได้ภายในขอบเขตที่ออกแบบ: ถอดผู้ดูแลคนอื่น (ยกเว้นเจ้าของ), เพิ่มคนนอกเข้ารายชื่อ (แต่คนนั้นยังต้องได้รับแชร์ชีตจึงอ่านข้อมูลได้ = ชั้นที่ 2 ยังกันอยู่), เปลี่ยนชีตหลักเป็นชีตคดีที่ตนสร้างเอง → บอตตอบสถานะคดี/สรุปรายเดือนจากข้อมูลปลอมในกลุ่ม LINE (บอตอ่านในนามเจ้าของ ถ้าเจ้าของเปิดชีตนั้นไม่ได้บอตจะตอบ "อ่านข้อมูลไม่ได้") · ไม่สามารถยกระดับเป็นเจ้าของ เปลี่ยนกลุ่ม LINE หรือดู token ได้ (ฟังก์ชันเจ้าของใช้ `requireOwner_`)

### SR-6 (ต่ำ) `cleanText_` ไม่ตัดอักขระควบคุมทิศทางบางตัว

- ตัด U+200B–200F และ U+2028–202E แล้ว แต่ไม่ตัด U+2066–2069 (bidi isolate), U+FEFF, U+061C, U+180E · ผู้ดูแลใส่ในชื่อเพื่อทำให้ชื่อแสดงสลับลำดับ/หลอกตาได้ (ไม่ใช่การแทรกโค้ด เพราะหน้าเว็บ escape แล้ว)
- แนวทางแก้: เพิ่ม `⁦-⁩﻿؜᠎` ใน regex ของ `cleanText_`

### SR-7 (ต่ำ) แคชข้อมูล 2 นาทีหลังเลิกแชร์ชีต

### ความเสี่ยงที่เหลือ (ยอมรับได้ ควรเขียนไว้ในเล่ม)

1. **SR-4:** ผู้ที่ไม่ล็อกอินเปิดลิงก์บอต (Execute as Me) แล้วเรียก `google.script.run.dailySummaryJob({triggerUid})` ด้วย triggerUid ที่ถูกต้อง จะผ่านทั้ง 2 เงื่อนไข (active user ว่าง, effective = เจ้าของ เหมือน trigger จริง) แยกไม่ได้จากฝั่งสคริปต์ · ไม่มีฟังก์ชันใดคืนค่า triggerUid (ความยากในการเดายังไม่ได้ยืนยันกับ Google จริง) · ผลสูงสุด: ส่งสรุปงวดที่ถึงกำหนดและยังไม่ส่งได้เร็วขึ้นภายในวันที่ 1–3 เนื้อหาเดียวกับที่ trigger จะส่ง ส่งซ้ำไม่ได้ (`SUMMARY_SENT_*` + retry key) ไม่ได้ข้อมูลกลับ
2. **SR-5 / Q45:** ผู้ดูแลที่ไม่ใช่เจ้าของยังเปลี่ยนชีตหลักเป็นชีตคดีที่ตนสร้างได้ (ตามการออกแบบ) บอตจะตอบจากชีตนั้นจนกว่าเจ้าของจะเห็นแถบแจ้งและแก้ · ระบบตรวจไม่ได้ว่าเจ้าของเปิดชีตได้ตอนผู้ดูแลกดตั้ง (ไม่ขอสิทธิ์ Drive) ใช้คำเตือน + `checkMainSheetAccess` + log แทน · แถบแจ้งแสดงเฉพาะการเปลี่ยนล่าสุด (ไม่มีประวัติทั้งหมด)
3. **SR-7:** เลิกแชร์ชีตใน Drive อย่างเดียว ผู้ใช้ยังได้ข้อมูลจากแคชของตนได้ไม่เกิน 60 วินาที (ลบในหน้า ผู้ใช้ มีผลทันที)
4. **SR-1:** พฤติกรรมจริงของ Script Properties กับอักขระครึ่งคู่ยังไม่ได้ยืนยันกับ Google จริง แต่หลังแก้ระบบไม่สร้างอักขระครึ่งคู่อีก จึงไม่ขึ้นกับพฤติกรรมนั้น
5. **SR-2:** ผู้มีสิทธิ์แก้โปรเจกต์ที่ลบทั้ง `DASH_CFG_*` และ `DASH_SETUP_DONE` จะกลับไปโหมดเดิมได้ (ถ้ายังมี `CASES_SHEET_ID`) ซึ่งเป็นสิทธิ์ระดับเจ้าของโปรเจกต์อยู่แล้ว README บอกให้ลบ `CASES_SHEET_ID` / `LAB_SHEET_ID` ไปพร้อมกันเมื่อกู้คืน
