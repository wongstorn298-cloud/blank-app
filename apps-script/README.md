# คู่มือติดตั้ง Dashboard งานตรวจ DNA บน Google Apps Script

คู่มือนี้เขียนสำหรับคนที่ไม่เคยใช้ Apps Script ทำตามทีละข้อจากบนลงล่าง ใช้เวลาประมาณ 30 นาที

เมื่อติดตั้งเสร็จ จะได้ลิงก์ Dashboard หนึ่งลิงก์ คนที่มีอีเมลอยู่ในแท็บ **ผู้ใช้** เปิดดูได้ ส่วนคนอื่นจะเห็นหน้า "ไม่มีสิทธิ์เข้าถึง" ตัว Google Sheet ยังเป็นแบบส่วนตัว ไม่ต้องตั้งให้ "ทุกคนที่มีลิงก์" เปิดได้

## ไฟล์ในโฟลเดอร์นี้

| ไฟล์ในโฟลเดอร์ `apps-script/` | ชื่อไฟล์ใน Apps Script editor | หน้าที่ |
|---|---|---|
| `Code.gs` | `Code.gs` (มีอยู่แล้วตอนสร้างโปรเจกต์) | เปิดหน้าเว็บ ตรวจสิทธิ์ และอ่านข้อมูลจาก Sheet |
| `Stats.gs` | `Stats.gs` | คำนวณสถิติ (LINE bot ใช้ชุดเดียวกัน ตัวเลขจึงตรงกับ Dashboard) |
| `Index.html` | `Index.html` | หน้าตา Dashboard |
| `LineBot.gs` | `LineBot.gs` | LINE bot: รับข้อความจากกลุ่ม (doPost) ตอบสถานะคดี/คดีค้าง โหมดตั้งค่าหา groupId |
| `Intent.gs` | `Intent.gs` | แยกว่าข้อความเรียกบอตหรือไม่ และถามอะไร (กฎก่อน ค่อยใช้ Gemini) |
| `Summary.gs` | `Summary.gs` | สรุปรายเดือน/รายปีเข้ากลุ่ม LINE อัตโนมัติ |
| `appsscript.json` | `appsscript.json` (ต้องเปิดให้แสดงก่อน ดูขั้นที่ 3) | การตั้งค่าโปรเจกต์ (เวลาไทย และสิทธิ์ที่ขอ) |
| `test/` | ไม่ต้องคัดลอก | ชุดทดสอบด้วยข้อมูลจำลอง |

## ขั้นที่ 1 · เตรียม Google Sheet

ใช้ Google Sheet 2 ไฟล์ คือ **ชีตคดี** (มีแท็บ `ข้อมูลคดี`) และ **ชีตงานตรวจ** (มีแท็บ `ข้อมูลเคส`, `ข้อมูลงบ`, `ข้อมูล Lot` และ `หมายเหตุ` ถ้ามี) ชื่อแท็บและหัวคอลัมน์ต้องตรงตาม `docs/data-schema.md`

### 1.1 เพิ่มแท็บ "ผู้ใช้" ในชีตคดี

1. เปิดชีตคดี กดเครื่องหมาย **+** มุมซ้ายล่างเพื่อเพิ่มแท็บ แล้วดับเบิลคลิกชื่อแท็บ เปลี่ยนเป็น `ผู้ใช้` (สะกดให้ตรง)
2. พิมพ์หัวคอลัมน์ในแถวที่ 1 ว่า `อีเมล` · `ชื่อ` · `หมายเหตุ`
3. ใส่อีเมลบัญชี Google ของคนที่ให้เปิด Dashboard ได้ คนละ 1 แถว **ใส่อีเมลของคุณเองด้วย**

| อีเมล | ชื่อ | หมายเหตุ |
|---|---|---|
| `staff1@example.com` | เจ้าหน้าที่ ก | ตัวอย่าง |

> ตัวพิมพ์ใหญ่หรือเล็กไม่มีผล ระบบเทียบให้เอง

### 1.2 แชร์ชีตให้ผู้ใช้เป็น "ผู้มีสิทธิ์อ่าน"

ทำกับ**ทั้งสองชีต**: กดปุ่ม **แชร์** มุมขวาบน ใส่อีเมลทุกคนในแท็บ `ผู้ใช้` แล้วเลือกสิทธิ์ **ผู้มีสิทธิ์อ่าน (Viewer)**

- **ห้าม**ตั้ง "การเข้าถึงทั่วไป" เป็น "ทุกคนที่มีลิงก์" ให้คงเป็น **จำกัด**
- ทำไมต้องแชร์ อ่านได้ที่หัวข้อ [เหตุผลที่ตั้งค่า Deploy แบบนี้](#เหตุผลที่ตั้งค่า-deploy-แบบนี้)

### 1.3 จด Sheet ID

Sheet ID คือข้อความยาวในลิงก์ของชีต ระหว่าง `/d/` กับ `/edit` เช่น

```
https://docs.google.com/spreadsheets/d/【ตรงนี้คือ Sheet ID】/edit#gid=0
```

จด ID ของชีตคดี และของชีตงานตรวจ ไว้ใช้ในขั้นที่ 4 (อย่าส่ง ID ลงกลุ่มแชตหรือใส่ในไฟล์ที่ขึ้น GitHub)

## ขั้นที่ 2 · สร้างโปรเจกต์ Apps Script

1. เข้า <https://script.google.com> ด้วยบัญชีที่เป็นเจ้าของชีต
2. กด **โปรเจกต์ใหม่ (New project)**
3. กดชื่อ "โปรเจกต์ที่ไม่มีชื่อ" มุมซ้ายบน แล้วตั้งชื่อ เช่น `Dashboard งานตรวจ DNA` (ชื่อนี้จะขึ้นบนหน้าขออนุญาตของ Google)

## ขั้นที่ 3 · คัดลอกไฟล์ไปวาง

ทำทีละไฟล์ เปิดไฟล์ใน GitHub (หรือในเครื่อง) กด Raw หรือเลือกทั้งหมด แล้วคัดลอก

1. **Code.gs** · ในแถบซ้ายของ editor คลิก `Code.gs` ลบโค้ดเดิม (`function myFunction…`) ออกทั้งหมด แล้ววางเนื้อหาจาก `apps-script/Code.gs`
2. **Stats.gs** · กด **+** ข้างคำว่า "ไฟล์ (Files)" → **สคริปต์ (Script)** → พิมพ์ชื่อ `Stats` (ไม่ต้องพิมพ์ .gs) → ลบโค้ดเดิม → วางเนื้อหาจาก `apps-script/Stats.gs`
3. **Index.html** · กด **+** → **HTML** → พิมพ์ชื่อ `Index` (I ตัวใหญ่ ไม่ต้องพิมพ์ .html) → ลบโค้ดเดิม → วางเนื้อหาจาก `apps-script/Index.html` (ไฟล์ยาว ~170 KB เพราะมีโลโก้หน่วยฝังอยู่ ให้แน่ใจว่าคัดลอกครบถึง `</html>` บรรทัดสุดท้าย)
4. **appsscript.json** · กดรูป **เฟือง (การตั้งค่าโปรเจกต์ / Project Settings)** แถบซ้าย → ติ๊ก **แสดงไฟล์ Manifest "appsscript.json" ในเครื่องมือแก้ไข** → กลับไปหน้า **เครื่องมือแก้ไข (Editor)** (รูป `< >`) → คลิก `appsscript.json` → ลบของเดิม → วางเนื้อหาจาก `apps-script/appsscript.json`
5. **LineBot.gs / Intent.gs / Summary.gs** · ทำแบบเดียวกับ Stats.gs (ชื่อ `LineBot`, `Intent`, `Summary`) — ถ้ายังไม่ทำ LINE bot ก็วางไว้ได้เลย ไม่มีผลกับ Dashboard
6. กดรูป **แผ่นดิสก์ (บันทึก)** หรือ Ctrl+S

## ขั้นที่ 4 · ตั้ง Script Properties (ที่เก็บ Sheet ID)

1. กดรูป **เฟือง (Project Settings)** → เลื่อนลงล่างสุดถึง **คุณสมบัติของสคริปต์ (Script Properties)** → **เพิ่มคุณสมบัติของสคริปต์**
2. เพิ่มทีละรายการ:

| คุณสมบัติ (Property) | ค่า (Value) | จำเป็น |
|---|---|---|
| `CASES_SHEET_ID` | Sheet ID ของชีตคดี | ต้องมี |
| `LAB_SHEET_ID` | Sheet ID ของชีตงานตรวจ | ถ้าไม่ใส่ Dashboard จะมีเฉพาะชุดคดี |
| `ADMIN_CONTACT` | ข้อความบอกคนที่ไม่มีสิทธิ์ว่าให้ติดต่อใคร เช่น `หัวหน้ากลุ่มงาน (โทรภายใน)` | ไม่บังคับ |

3. กด **บันทึกคุณสมบัติของสคริปต์**

## ขั้นที่ 5 · ทดสอบการตั้งค่า (ไม่บังคับ แต่แนะนำ)

1. กลับไปหน้า Editor เปิด `Code.gs`
2. ที่แถบบน เลือกฟังก์ชัน **checkSetup** แล้วกด **เรียกใช้ (Run)**
3. ครั้งแรกจะมีหน้าต่างขออนุญาต ทำตาม [ขั้นที่ 7](#ขั้นที่-7--หน้าจอ-google-ยังไม่ได้ยืนยันแอปนี้-unsafe)
4. ดูผลที่ **บันทึกการดำเนินการ (Execution log)** ด้านล่าง ควรเห็นประมาณนี้ (แสดงเฉพาะจำนวนแถว ไม่แสดงข้อมูลคดี)

```
อีเมลของคุณ: …@… (อยู่ในแท็บ ผู้ใช้ แล้ว)
คดีส่งตรวจ DNA (รายคดี): ข้อมูลคดี 731 แถว
งานตรวจ DNA (Lot / งบประมาณ): ข้อมูลเคส 58 แถว, ข้อมูลงบ 39 แถว, ข้อมูล Lot 86 แถว, หมายเหตุ 4 แถว
```

ถ้าขึ้น "ไม่มีสิทธิ์เข้าถึงข้อมูล" แปลว่าอีเมลของคุณยังไม่อยู่ในแท็บ `ผู้ใช้`

## ขั้นที่ 6 · Deploy เป็น Web app

1. กดปุ่มสีน้ำเงิน **การทำให้ใช้งานได้ (Deploy)** มุมขวาบน → **การทำให้ใช้งานได้รายการใหม่ (New deployment)**
2. กดรูป **เฟือง** ข้าง "เลือกประเภท" → เลือก **เว็บแอป (Web app)**
3. ตั้งค่าตามนี้ **ทุกช่อง**:

| ช่อง | ค่าที่ต้องเลือก |
|---|---|
| คำอธิบาย (Description) | `v1` (หรือข้อความอะไรก็ได้) |
| ดำเนินการในฐานะ (Execute as) | **ผู้ใช้ที่เข้าถึงเว็บแอป (User accessing the web app)** |
| ผู้ที่มีสิทธิ์เข้าถึง (Who has access) | **ทุกคนที่มีบัญชี Google (Anyone with Google account)** |

4. กด **ทำให้ใช้งานได้ (Deploy)** → ถ้ามีหน้าขออนุญาต ทำตามขั้นที่ 7
5. คัดลอก **URL ของเว็บแอป** (ลงท้ายด้วย `/exec`) นี่คือลิงก์ Dashboard ที่ส่งให้เจ้าหน้าที่

> ⚠️ ห้ามเลือก Execute as = **ฉัน (Me)** สำหรับ Dashboard เพราะ Google จะไม่บอกอีเมลของคนที่ใช้ Gmail ทั่วไป ระบบจะปฏิเสธทุกคนยกเว้นคุณ (อ่านเหตุผลด้านล่าง)

## ขั้นที่ 7 · หน้าจอ "Google ยังไม่ได้ยืนยันแอปนี้" (unsafe)

เพราะแอปนี้เราเขียนเองและไม่ได้ส่งให้ Google ตรวจ จึงจะเห็นคำเตือนนี้ **ทุกคนที่เปิดครั้งแรกจะเห็น 1 ครั้ง** (ไม่ใช่แค่คุณ) ควรบอกเจ้าหน้าที่ล่วงหน้า

1. หน้า "ต้องได้รับสิทธิ์ (Authorization required)" → กด **ตรวจสอบสิทธิ์ (Review permissions)** → เลือกบัญชี Google
2. หน้า "Google ยังไม่ได้ยืนยันแอปนี้ (Google hasn't verified this app)" → กด **ขั้นสูง (Advanced)** ตัวเล็กด้านล่าง
3. กด **ไปที่ Dashboard งานตรวจ DNA (ไม่ปลอดภัย) / Go to … (unsafe)**
4. ตรวจรายการสิทธิ์ ควรมี 4 อย่าง → กด **อนุญาต (Allow)** (ถ้ามีช่องให้ติ๊ก ให้ติ๊กทุกช่อง)
   - **ดูอีเมลของคุณ** และ **ดูสเปรดชีต Google ของคุณ** (อ่านอย่างเดียว แก้ไม่ได้) — Dashboard ใช้
   - **เชื่อมต่อกับบริการภายนอก** และ **อนุญาตให้แอปพลิเคชันนี้ทำงานเมื่อคุณไม่ได้ใช้งาน** — LINE bot และสรุปอัตโนมัติใช้ (Google ขอสิทธิ์ทั้งโปรเจกต์ในครั้งเดียว ผู้ใช้ Dashboard จึงเห็นด้วย แต่โค้ดของ Dashboard ไม่ได้ใช้ 2 ข้อนี้ ฟังก์ชันส่ง LINE ทุกตัวเรียกได้เฉพาะเจ้าของ/trigger)

ถ้าเห็นสิทธิ์อื่นที่ไม่ได้ระบุไว้ ให้หยุดและตรวจว่าคัดลอก `appsscript.json` ถูกต้อง

## ขั้นที่ 8 · ทดสอบลิงก์

1. เปิด URL `/exec` ด้วยบัญชีที่อยู่ในแท็บ `ผู้ใช้` → ต้องเห็น Dashboard
2. เปิดด้วยบัญชีอื่น (หรือหน้าต่างไม่ระบุตัวตน แล้วล็อกอินบัญชีที่ไม่อยู่ในรายชื่อ) → ต้องเห็นหน้า **ไม่มีสิทธิ์เข้าถึง** พร้อมอีเมลของบัญชีนั้น

## เพิ่ม / ลบ ผู้ใช้

**เพิ่มคน:**
1. ใส่อีเมลในแท็บ `ผู้ใช้` ของชีตคดี
2. แชร์**ทั้งสองชีต**ให้อีเมลนั้นเป็น **ผู้มีสิทธิ์อ่าน**
3. ส่งลิงก์ `/exec` ให้ และบอกเรื่องหน้าจอ unsafe (ขั้นที่ 7)

**ลบคน:**
1. ลบแถวของคนนั้นในแท็บ `ผู้ใช้`
2. เอาชื่อออกจากการแชร์ของ**ทั้งสองชีต** (แชร์ → เลือกชื่อ → นำออก)
3. มีผลภายในประมาณ 1 นาที (ระบบจำผลตรวจสิทธิ์ไว้ 1 นาที)

> ต้องทำทั้ง 2 อย่างเสมอ: แท็บ `ผู้ใช้` คุมการเปิด Dashboard ส่วนการแชร์คุมการเปิดตัวชีตโดยตรง

## เมื่อแก้โค้ด (อัปเดตเวอร์ชัน)

1. วางโค้ดใหม่ทับไฟล์เดิมใน editor แล้วบันทึก
2. **Deploy → จัดการการทำให้ใช้งานได้ (Manage deployments)**
3. เลือกรายการเว็บแอปที่มีอยู่ → กดรูป **ดินสอ (แก้ไข)**
4. ช่อง **เวอร์ชัน (Version)** เลือก **เวอร์ชันใหม่ (New version)** → กด **ทำให้ใช้งานได้ (Deploy)**
5. ลิงก์ `/exec` เดิมใช้ได้ต่อ ไม่ต้องส่งลิงก์ใหม่

> อย่ากด "การทำให้ใช้งานได้รายการใหม่ (New deployment)" ตอนอัปเดต เพราะจะได้ลิงก์ใหม่ ลิงก์เก่าจะยังแสดงโค้ดเก่า
> ถ้าแก้โค้ดแล้วยังไม่ Deploy เวอร์ชันใหม่ ผู้ใช้จะยังเห็นของเดิม

## แก้ปัญหา

| อาการ | สาเหตุที่พบบ่อย | วิธีแก้ |
|---|---|---|
| ทุกคนเห็น "ไม่มีสิทธิ์" และขึ้น "ระบบไม่ทราบอีเมลของคุณ" | Deploy แบบ Execute as = Me | แก้ Deploy เป็น **User accessing the web app** (ขั้นที่ 6) แล้ว Deploy เวอร์ชันใหม่ |
| "บัญชีนี้ยังไม่ได้รับสิทธิ์ ผู้มีสิทธิ์อ่าน" | ยังไม่ได้แชร์ชีตคดีให้อีเมลนี้ | แชร์ชีตเป็นผู้มีสิทธิ์อ่าน (ขั้นที่ 1.2) |
| "อีเมลนี้ยังไม่อยู่ในรายชื่อ" ทั้งที่ใส่แล้ว | สะกดอีเมลผิด / ใส่ผิดคอลัมน์ / หัวคอลัมน์ไม่ใช่ `อีเมล` | ตรวจแท็บ `ผู้ใช้` (เว้นวรรคหัวท้ายไม่มีผล) |
| ชุด "คดี" ขึ้นได้ แต่ชุด "งานตรวจ" ขึ้น "เปิด Google Sheet … ไม่ได้" | ยังไม่ได้แชร์ชีตงานตรวจ หรือ `LAB_SHEET_ID` ผิด | แชร์ชีตงานตรวจ / ตรวจ ID |
| "ไม่พบแท็บ ข้อมูลคดี" | ชื่อแท็บไม่ตรง | เปลี่ยนชื่อแท็บให้ตรง `ข้อมูลคดี` |
| แก้ข้อมูลในชีตแล้ว Dashboard ยังไม่เปลี่ยน | ระบบจำข้อมูลไว้ 2 นาที | รอ 2 นาที หน้าเว็บจะดึงใหม่เอง หรือกดรีเฟรชเบราว์เซอร์หลังครบ 2 นาที |
| แก้โค้ดแล้วไม่เห็นผล | ยังไม่ได้ Deploy เวอร์ชันใหม่ | ทำหัวข้อ "เมื่อแก้โค้ด" |
| เปิดลิงก์แล้วเลือกบัญชีผิด (ล็อกอินหลายบัญชี) | Google ใช้บัญชีแรกของเบราว์เซอร์ | เปิดหน้าต่างไม่ระบุตัวตน แล้วล็อกอินบัญชีที่ได้รับสิทธิ์บัญชีเดียว |
| "This app is blocked" / ขึ้นว่าแอปถูกบล็อก | บัญชีองค์กรบางแห่งห้ามแอปที่ยังไม่ยืนยัน | ใช้บัญชี Google ส่วนตัว หรือขอผู้ดูแลระบบขององค์กรอนุญาต |
| กด "เลือกไฟล์ .xlsx" แล้วขึ้นว่าโหลดตัวอ่านไม่ได้ | เครื่องต่อ cdnjs.cloudflare.com ไม่ได้ | ตรวจอินเทอร์เน็ต (ใช้เฉพาะตอนเปิดไฟล์ Excel ในเครื่อง) |
| ดูรายละเอียดข้อผิดพลาดฝั่งเซิร์ฟเวอร์ | | ใน editor กด **การดำเนินการ (Executions)** แถบซ้าย |

## เหตุผลที่ตั้งค่า Deploy แบบนี้

**ปัญหา:** ระบบต้องรู้อีเมลของคนที่เปิด จึงจะเทียบกับแท็บ `ผู้ใช้` ได้ เอกสารของ Google ระบุว่า `Session.getActiveUser().getEmail()` จะเป็น**ค่าว่าง**ในเว็บแอปที่ตั้ง "execute as me" ยกเว้นผู้ใช้อยู่ในโดเมน Google Workspace เดียวกับเจ้าของสคริปต์ ([Session.getActiveUser](https://developers.google.com/apps-script/reference/base/session#getActiveUser())) ผู้ใช้ Gmail ทั่วไปจึงจะถูกปฏิเสธทั้งหมด

**วิธีที่ใช้:** Deploy แบบ **Execute as: User accessing the web app** ([Web Apps](https://developers.google.com/apps-script/guides/web)) ผู้ใช้กดอนุญาตเองครั้งแรก Google จึงส่งอีเมลมาให้ และสคริปต์อ่านชีตด้วยสิทธิ์ของผู้ใช้คนนั้น ทำให้เกิดการป้องกัน 2 ชั้น:

1. ต้องมีอีเมลในแท็บ `ผู้ใช้` (ตรวจทุกครั้งที่หน้าเว็บขอข้อมูล ไม่ใช่แค่ตอนเปิดหน้า)
2. ต้องได้รับแชร์ชีตแบบผู้มีสิทธิ์อ่าน

**ข้อแลกเปลี่ยนที่ควรรู้:**
- ผู้ใช้ที่ได้รับแชร์จะเปิด**ตัวชีต**ได้โดยตรง เห็นทุกแท็บทุกคอลัมน์ (เช่น ชื่อผู้ตรวจ) ไม่ใช่เห็นแค่ใน Dashboard ถ้าไม่ต้องการ ให้ย้ายคอลัมน์ที่อ่อนไหวไปไว้ในชีตแยกที่ไม่แชร์ (คอลัมน์ `User ID (LINE)` เจ้าของตัดสินใจลบออกแล้ว ระบบไม่ใช้คอลัมน์นี้)
- ผู้ใช้ทุกคนต้องผ่านหน้าจอ unsafe ครั้งแรก (ขั้นที่ 7)
- ถ้าทุกคนที่ใช้อยู่ในโดเมน Google Workspace เดียวกับเจ้าของ (เช่น อีเมลหน่วยงานที่เป็น Workspace) จะใช้ Execute as = Me และไม่ต้องแชร์ชีตได้ แต่ถ้ามีบัญชี Gmail แม้แต่คนเดียว คนนั้นจะเข้าไม่ได้

## ความเป็นส่วนตัว (PDPA)

- หน้าเว็บได้รับเฉพาะคอลัมน์ที่ Dashboard ใช้ (เลข บก., เลขรายงาน, สภ., จังหวัด, วันที่, สถานะ, ประเภทคดี, ผู้ตรวจ, ของกลาง, นับในสถิติ, ข้อสังเกต) **ไม่ส่ง** เลขหนังสือนำส่ง ลงวันที่ และไม่มี DNA profile · ระบบไม่ใช้คอลัมน์ `User ID (LINE)` (ลบออกจากชีตได้เลย ถ้ายังมีก็ไม่ถูกส่ง)
- LINE bot ตอบสถานะคดีเฉพาะ สถานะ ประเภทคดี จำนวนของกลาง และวันที่ 3 ช่อง (ไม่มีชื่อผู้ตรวจ สภ. เลขรายงาน) · Gemini ได้รับเฉพาะข้อความคำถามที่ตัดตัวเลข ชื่อ อีเมล ลิงก์ ออกแล้ว ไม่เคยได้ข้อมูลจาก Sheet
- ไม่มี Sheet ID, token หรืออีเมลจริงในโค้ด ทั้งหมดอยู่ใน Script Properties และแท็บ `ผู้ใช้`
- ไฟล์ Excel ที่เลือกดูในหน้า "แหล่งข้อมูล" ถูกอ่านในเบราว์เซอร์เท่านั้น ไม่ถูกอัปโหลด
- ภาพหน้าจอสำหรับเล่มโครงงานให้ใช้ข้อมูลจำลองเท่านั้น

## LINE bot

ทำหลังจาก Dashboard ใช้งานได้แล้ว (ขั้นที่ 1–8) ใช้เวลาประมาณ 45 นาที ทุกขั้นทดสอบได้โดย**ยังไม่ส่งข้อความสรุปเข้ากลุ่มจริง** การส่งจริงครั้งแรกต้องให้เจ้าของโครงงานอนุมัติ (ขั้น L11)

### บอตทำอะไรได้ และเรียกอย่างไร

บอตอยู่ในกลุ่ม LINE เจ้าหน้าที่**กลุ่มเดียว** ข้อความทั่วไปในกลุ่มบอต**เงียบ** (ไม่ตอบ ไม่ส่งไปที่ไหน) จะตอบเฉพาะเมื่อ

| พิมพ์ในกลุ่ม | บอตตอบ |
|---|---|
| เลข บก. อย่างเดียว เช่น `123/2568`, `คดี ๑๒๓/๒๕๖๘`, `123/2568 ถึงไหนแล้ว` (ได้สูงสุด 3 เลข) | สถานะ, ประเภทคดี, จำนวนของกลาง, วันที่รับ / ตรวจเสร็จ / มารับผล |
| `คดีค้าง`, `งานค้าง`, `สรุปคดีค้าง`, `มีคดีค้างกี่คดี` (ทั้งข้อความ) | จำนวน "กำลังดำเนินการ" และ "เสร็จแล้ว รอรับผล" แยกกัน + เลข บก. ที่ค้างนานสุดกลุ่มละ 3 คดี |
| ขึ้นต้นด้วย `บอต` / `บอท` / `bot` แล้วเว้นวรรค หรือขึ้นต้นด้วย `/` หรือ @กล่าวถึงบอต เช่น `บอต คดีที่ยังไม่รับผลมีกี่คดี` | ถ้ามีเลข บก. หรือคำว่า ค้าง/ยังไม่รับผล → ตอบทันที · ถ้าไม่เข้าใจ → ถาม Gemini ว่าหมายถึงคำสั่งไหน แล้วตอบ (ถ้า Gemini ใช้ไม่ได้ ตอบวิธีใช้) · `บอต` เฉย ๆ = วิธีใช้ |

ข้อความที่มีเลข บก. **ปนอยู่ในประโยค** เช่น "ส่งของกลางคดี 123/2568 แล้วนะ" บอตจะเงียบ (ถ้าต้องการถาม ให้ขึ้นต้นด้วย `บอต`)

> **กติกานับคดีค้าง** เหมือน Dashboard: สถานะ `รับผลไปแล้ว` = ไม่ค้าง, มีคำว่า `รอรับผล` = เสร็จแล้ว รอรับผล, อื่น ๆ **รวมช่องสถานะว่าง** = กำลังดำเนินการ (บอตจะบอกว่ามีกี่คดีที่ช่องสถานะว่าง ให้ตามกรอก)

### L1 · สร้าง LINE Official Account และเปิด Messaging API

1. เข้า <https://manager.line.biz> → **สร้างบัญชี LINE Official Account** (สมัคร LINE Business ID ด้วยบัญชี LINE ของคุณ) กรอกแบบฟอร์มให้ครบ ชื่อบัญชี เช่น `บอตติดตามคดี DNA`
2. ใน LINE Official Account Manager เลือกบัญชีนั้น → **ตั้งค่า (Settings)** มุมขวาบน → เมนูซ้าย **Messaging API** → กด **ใช้ Messaging API (Enable Messaging API)**
3. ระบบให้เลือก/สร้าง **Provider** (เช่น ชื่อหน่วยงานหรือชื่อโครงงาน) — เลือกแล้วเปลี่ยนภายหลังไม่ได้
4. ตั้งแต่ 4 ก.ย. 2567 สร้าง Messaging API channel จาก LINE Developers Console โดยตรงไม่ได้แล้ว ต้องเปิดจากขั้นนี้ ([LINE: Getting started](https://developers.line.biz/en/docs/messaging-api/getting-started/))

### L2 · ปิดข้อความอัตโนมัติ และอนุญาตให้เข้ากลุ่ม

ใน LINE Official Account Manager → **ตั้งค่า** →

1. **การตอบกลับ (Response settings)**: เปิด **Webhook**, ปิด **ข้อความตอบกลับอัตโนมัติ (Auto-response)**, ปิด **ข้อความทักทาย (Greeting message)** — ถ้าไม่ปิด บอตจะตอบข้อความสำเร็จรูปของ LINE ทุกข้อความในกลุ่ม
2. **ตั้งค่าบัญชี (Account settings)** → **อนุญาตให้บัญชีเข้าร่วมแชทกลุ่มและแชทหลายคน (Allow account to join groups and multi-person chats)** → เปิด

### L3 · Channel access token

1. เข้า <https://developers.line.biz/console> ด้วยบัญชีเดียวกัน → เลือก Provider → เลือก channel ของบอต → แท็บ **Messaging API**
2. เลื่อนล่างสุด **Channel access token (long-lived)** → กด **Issue** → คัดลอกค่า (ยาวมาก) เก็บไว้ใช้ในขั้น L7 **อย่าส่งลงแชตหรือใส่ในไฟล์ที่ขึ้น GitHub**
3. ที่แท็บเดียวกัน ถ้ามีช่อง **Allow bot to join group chats** ให้เป็น Enabled (ลิงก์ไปที่ L2)

### L4 · ตั้ง Script Properties ชุดแรก และสร้าง token ของ webhook

1. Apps Script → **เฟือง (Project Settings)** → **Script Properties** → เพิ่ม `ADMIN_EMAIL` = อีเมลบัญชี Google ที่เป็นเจ้าของสคริปต์ (ฟังก์ชันผู้ดูแลทุกตัวรันได้เฉพาะบัญชีนี้)
2. กลับไปหน้า Editor เปิด `LineBot.gs` เลือกฟังก์ชัน **makeWebhookToken** → **Run** (ครั้งแรกมีหน้าขออนุญาต ทำตามขั้นที่ 7)
3. กลับไป Script Properties จะเห็น `WEBHOOK_TOKEN` (ตัวอักษรสุ่ม 64 ตัว) — นี่คือรหัสลับของ webhook

### L5 · Deploy แยกสำหรับบอต (ห้ามแก้รายการ Deploy ของ Dashboard)

1. **Deploy → New deployment** → เฟือง → **Web app**
2. ตั้งค่า:

| ช่อง | ค่า |
|---|---|
| Description | `LINE bot` |
| Execute as | **Me (อีเมลของคุณ)** — LINE ไม่มีบัญชี Google จึงต้องทำงานในนามเจ้าของ |
| Who has access | **Anyone** (ไม่ใช่ "Anyone with Google account") |

3. กด **Deploy** → คัดลอก **Web app URL** (ลงท้าย `/exec`) — ลิงก์นี้ใช้กับ LINE เท่านั้น **ไม่ต้องส่งให้ใคร**
4. รายการ Deploy ของ Dashboard (Execute as: User accessing) **คงไว้เหมือนเดิม** ตอนนี้จะมี 2 รายการ
5. ทำไมลิงก์บอตไม่รั่วข้อมูล Dashboard: ถ้ามีคนเปิดลิงก์บอตในเบราว์เซอร์ ระบบเห็นว่ากำลังทำงานในนามบัญชีอื่น (เจ้าของ) ไม่ใช่คนที่เปิด จึงแสดงหน้า "ไม่มีสิทธิ์เข้าถึง" และฟังก์ชันข้อมูลทุกตัวปฏิเสธ (มีชุดทดสอบยืนยัน)
6. เมื่อแก้โค้ดในอนาคต ต้องอัปเดต**ทั้ง 2 รายการ** (Manage deployments → ดินสอ → New version ทีละรายการ)

### L6 · ตั้ง Webhook URL ใน LINE

1. LINE Developers Console → channel → แท็บ **Messaging API** → **Webhook URL** → **Edit**
2. ใส่ `URL จาก L5` + `?token=` + `ค่า WEBHOOK_TOKEN` เช่น
   ```
   https://script.google.com/macros/s/【รหัส Deploy ของบอต】/exec?token=【WEBHOOK_TOKEN】
   ```
3. **Update** → เปิด **Use webhook**
4. ปิด **Webhook redelivery** (ค่าเริ่มต้นปิดอยู่แล้ว ให้คงไว้) — ระบบไม่ตอบข้อความที่ส่งซ้ำอยู่แล้ว
5. กด **Verify**: ถ้าขึ้น Success ดี · ถ้าขึ้นข้อผิดพลาด เช่น `302 Found` หรือ timeout **ยังใช้งานได้** (ดู [หมายเหตุ Verify และ 302](#หมายเหตุ-verify-และ-302)) ให้ทดสอบจริงในขั้น L8 แทน

> Token อยู่ใน URL เพราะ Apps Script อ่านลายเซ็น `x-line-signature` ไม่ได้ (ดู [ความปลอดภัยของ webhook](#ความปลอดภัยของ-webhook)) — ถ้า URL หลุด ให้ลบ `WEBHOOK_TOKEN` แล้วรัน makeWebhookToken ใหม่ และแก้ Webhook URL

### L7 · ตั้ง Script Properties ที่เหลือ

| Property | ค่า | จำเป็น |
|---|---|---|
| `LINE_CHANNEL_TOKEN` | Channel access token จาก L3 | ต้องมี |
| `WEBHOOK_TOKEN` | สร้างแล้วใน L4 | ต้องมี |
| `ADMIN_EMAIL` | ใส่แล้วใน L4 | ต้องมี |
| `ALLOWED_GROUP_ID` | ได้จาก L8 (ยังไม่ต้องใส่ตอนนี้) | ต้องมี |
| `DASHBOARD_URL` | ลิงก์ `/exec` ของ **Dashboard** (ขั้นที่ 6) ใช้แนบท้ายสรุป | แนะนำ |
| `GEMINI_API_KEY` | จาก L10 | ไม่บังคับ (ไม่ใส่ = บอตใช้แค่กฎ ข้อความที่ไม่เข้าใจตอบวิธีใช้) |
| `GEMINI_MODEL` | เว้นว่างได้ ค่าเริ่มต้น `gemini-3.5-flash-lite` | ไม่บังคับ |
| `GEMINI_MAX_PER_HOUR` | เว้นว่างได้ ค่าเริ่มต้น 30 ครั้ง/ชั่วโมง | ไม่บังคับ |
| `PUSH_ENABLED` | `yes` เมื่อเจ้าของโครงงานอนุมัติให้ส่งสรุปจริง (L11) | **ยังไม่ต้องใส่** |

### L8 · เพิ่มบอตเข้ากลุ่ม และหา groupId (โหมดตั้งค่า)

ระบบไม่ให้บอตพิมพ์ groupId ลงแชต (ระหว่างตั้งค่ายังไม่มีรายชื่อกลุ่มที่อนุญาต บอตจะต้องตอบทุกกลุ่ม และรหัสจะค้างอยู่ในแชต) จึงบันทึกไว้ใน Script Properties ซึ่งเห็นเฉพาะเจ้าของ

1. Editor → `LineBot.gs` → เลือก **startSetupMode** → **Run** (เปิดโหมดตั้งค่า 60 นาที บอตยังไม่ตอบอะไรในแชต)
2. ในแอป LINE: เปิดกลุ่มเจ้าหน้าที่ → เมนู → **เชิญ** → ค้นชื่อบัญชีบอต (หรือเพิ่มบอตเป็นเพื่อนก่อนด้วย QR code ในแท็บ Messaging API) → เชิญเข้ากลุ่ม
3. (ถ้าบอตอยู่ในกลุ่มแล้ว ให้พิมพ์ข้อความอะไรก็ได้ในกลุ่ม 1 ครั้งแทน)
4. Editor → เลือก **showSetupGroups** → **Run** → ดู Execution log ต้องเห็น `กลุ่มที่พบ: 1) C…`
5. ถ้าพบ 1 กลุ่ม เลือก **allowSeenGroup** → **Run** (ตั้ง `ALLOWED_GROUP_ID` ให้และปิดโหมดตั้งค่า) · ถ้าพบหลายกลุ่ม คัดลอกรหัสของกลุ่มเจ้าหน้าที่ไปใส่ `ALLOWED_GROUP_ID` เองใน Script Properties

พิมพ์ในกลุ่มทีละข้อความ:

| พิมพ์ | ควรเห็น |
|---|---|
| `สวัสดี` | บอตเงียบ |
| `บอต` | วิธีใช้บอต |
| เลข บก. ที่มีจริง | สถานะคดีนั้น |
| `9999/2599` | ไม่พบคดี |
| `คดีค้าง` | จำนวน 2 กลุ่ม ตรงกับ Dashboard เมนู "ระยะเวลาและงานค้าง" |

ถ้าบอตไม่ตอบเลย: ตรวจ Executions ใน Apps Script (มี doPost ทำงานไหม) · Webhook URL มี `?token=` ถูกไหม · `ALLOWED_GROUP_ID` ถูกกลุ่มไหม · ปิด auto-response แล้วหรือยัง · Deploy เวอร์ชันล่าสุดหรือยัง

### L10 · Gemini API key ฟรี (ไม่บังคับ)

1. เข้า <https://aistudio.google.com/apikey> ด้วยบัญชี Google → **Create API key** → คัดลอกไปใส่ `GEMINI_API_KEY`
2. แบบฟรี Google ระบุว่าข้อมูลที่ส่งอาจถูกใช้ปรับปรุงผลิตภัณฑ์และมีคนอ่านได้ ([Gemini API pricing](https://ai.google.dev/gemini-api/docs/pricing), [Terms](https://ai.google.dev/gemini-api/terms)) ระบบจึงส่งเฉพาะข้อความคำถามที่**ตัดตัวเลขทั้งหมด (รวมเลขคดี) ชื่อที่มีคำนำหน้า อีเมล ลิงก์ ชื่อหน่วย** ออกแล้ว ไม่ส่ง groupId / userId และไม่เคยส่งข้อมูลจาก Sheet
3. Gemini ตอบได้แค่ว่าคำถามเป็นคำสั่งไหน (`{"intent": …}`) เลขคดีระบบดึงจากข้อความเดิมเอง คำตอบทั้งหมดสร้างจากโค้ด

### L11 · สรุปอัตโนมัติ: ตรวจตัวอย่าง → ตั้ง trigger → ขออนุมัติก่อนส่งจริง

1. Editor → `Summary.gs` → ดูตัวอย่าง (ไม่ส่ง): เลือก **previewSummary** → Run = สรุปเดือนที่แล้ว · **previewYearSummary** → Run = สรุปปีที่แล้ว · ดูข้อความใน Execution log
   - ดูเดือน/ปีอื่น: กด **+** → Script → ตั้งชื่อ `Try` แล้ววาง `function tryIt() { previewSummary(2569, 10); previewYearSummary(2568); }` → บันทึก → เลือก **tryIt** → Run (ลบไฟล์ Try ทิ้งได้หลังดูเสร็จ)
2. เทียบตัวเลขกับ Dashboard (เลือกเดือน/ปีเดียวกัน) ต้องตรงกัน
3. เลือก **installTriggers** → Run (สร้าง trigger รายวัน 08:00–09:00 น. เวลาไทย รันซ้ำได้ ไม่สร้างซ้ำ) ดูได้ที่เมนูรูปนาฬิกา **Triggers**
4. ตราบใดที่ยังไม่มี `PUSH_ENABLED = yes` trigger จะ**ไม่ส่ง** แค่เขียนข้อความตัวอย่างลง Executions ทุกวันที่ 1
5. **ส่งเอกสารตัวอย่างให้เจ้าของโครงงานอนุมัติ** แล้วจึงเพิ่ม `PUSH_ENABLED` = `yes` — วันที่ 1 ถัดไประบบจะส่งสรุปเดือนก่อนหน้า (1 ม.ค. ส่งสรุปธันวาคม + สรุปทั้งปีในครั้งเดียว)
6. หยุดส่ง: ลบ `PUSH_ENABLED` หรือรัน **removeTriggers**

กันส่งซ้ำ: ระบบจำงวดที่ส่งแล้วใน `SUMMARY_SENT_MONTH` / `SUMMARY_SENT_YEAR` (อย่าแก้เอง) ใช้ LockService กันทำงานซ้อน และใช้ retry key ของ LINE ถ้าวันที่ 1 ส่งไม่สำเร็จ ระบบลองใหม่วันที่ 2–3

### โควตาข้อความ LINE

- **ตอบคำถาม (reply) ไม่นับโควตา** · **สรุปอัตโนมัติ (push) นับตามจำนวนสมาชิกในกลุ่มต่อการส่ง 1 ครั้ง** ไม่ว่าในครั้งนั้นมีกี่ข้อความ ([LINE: Messaging API pricing](https://developers.line.biz/en/docs/messaging-api/pricing/))
- กลุ่ม ≈ 20 คน → เดือนปกติ ≈ 20 ข้อความ/เดือน · มกราคมส่งสรุปเดือน + ปีในคำขอเดียว ≈ 20 ข้อความ (ถ้าต้องแยกเป็น 2 คำขอจะเป็น ≈ 40) — อยู่ในโควตาฟรีของแพ็กเกจเริ่มต้น (ตรวจจำนวนโควตาของประเทศไทยในหน้า LINE Official Account ของคุณ เมนู ตั้งค่า → แพ็กเกจ)

### ความปลอดภัยของ webhook

LINE แนะนำให้ตรวจลายเซ็น `x-line-signature` (HMAC-SHA256 ของ body ด้วย channel secret) ก่อนประมวลผล ([LINE: Verify webhook signature](https://developers.line.biz/en/docs/messaging-api/verify-webhook-signature/)) แต่ออบเจ็กต์ `e` ของ `doPost` ใน Apps Script มีแค่ `parameter`, `parameters`, `queryString`, `pathInfo`, `contentLength`, `postData` **ไม่มี header** ([Apps Script: Web apps](https://developers.google.com/apps-script/guides/web)) จึงตรวจลายเซ็นไม่ได้ มาตรการทดแทนที่ทำไว้:

1. **รหัสลับใน URL** (`?token=` 64 ตัวอักษรสุ่ม) เทียบแบบใช้เวลาคงที่ ไม่ตรง/ไม่มี/ยังไม่ตั้ง = ทิ้งทั้งคำขอ ไม่อ่านชีต
2. **รายชื่อกลุ่มที่อนุญาต** ตอบเฉพาะ `ALLOWED_GROUP_ID` แชตส่วนตัว กลุ่มอื่น ห้องแชต = เงียบ
3. **ตอบด้วย reply token เท่านั้น** ข้อมูลไปถึงได้แค่แชตที่ LINE ออก reply token ให้ คำขอปลอมไม่มี reply token จริง LINE จึงปฏิเสธ — ข้อมูลไม่เคยอยู่ในคำตอบ HTTP ของ doPost (ตอบ `OK` เหมือนกันทุกกรณี ไม่มีข้อความ error)
4. **จำกัด** ขนาด body ≤ 100 KB, ≤ 20 event ต่อคำขอ, ข้อความ ≤ 1,000 ตัวอักษร, ทิ้ง event ซ้ำ (`webhookEventId`) / redelivery / event เก่ากว่า 5 นาที, Gemini ≤ 30 ครั้ง/ชั่วโมง
5. **ข้อมูลน้อยที่สุด** คำตอบไม่มีชื่อผู้ตรวจ สภ. เลขรายงาน · สรุปไม่มีเลขคดี
6. ความเสี่ยงที่เหลือ: ถ้า URL พร้อม token หลุด ผู้ไม่หวังดีส่งคำขอปลอมได้ แต่จะได้แค่ทำให้บอตเรียก reply ด้วย token ปลอม (LINE ปฏิเสธ) หรือใช้โควตา Gemini (ถูกจำกัดต่อชั่วโมง) — เปลี่ยน token ได้ทันทีตาม L6

### หมายเหตุ Verify และ 302

- LINE ต้องการให้ webhook ตอบสถานะ `200` ([Verify webhook URL](https://developers.line.biz/en/docs/messaging-api/verify-webhook-url/)) และนับเป็นข้อผิดพลาดถ้าไม่ตอบภายใน 2 วินาทีหรือตอบรหัสที่ไม่ใช่ 2xx ([Webhook error statistics](https://developers.line.biz/en/docs/messaging-api/check-webhook-error-statistics/))
- Apps Script web app รันโค้ด `doPost` ก่อน แล้วตอบผลเป็นการ redirect (302) ไปยัง `script.googleusercontent.com` เอกสาร Google ไม่ได้ระบุเรื่องนี้ แต่เป็นพฤติกรรมที่ผู้ใช้ทั่วไปพบ (เช่น การทดสอบด้วย curl ต้องใส่ `-L`) และ Apps Script ตั้งรหัสสถานะเองไม่ได้ โค้ดจึงตอบ `ContentService` ข้อความ `OK` ให้เร็วที่สุด
- ผลที่อาจเห็น: ปุ่ม Verify ขึ้นข้อผิดพลาด และสถิติข้อผิดพลาด webhook ใน Console มีรายการ แต่**บอตยังตอบได้** เพราะ reply ถูกส่งระหว่าง doPost ทำงานแล้ว — ปิด redelivery ไว้ (L6) จึงไม่มีข้อความซ้ำ และระบบทิ้ง event ซ้ำอยู่แล้ว
